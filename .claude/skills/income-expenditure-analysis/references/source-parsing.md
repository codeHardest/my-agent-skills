# 各来源解析配方与已知坑

解析是整条链的地基：**分类前先把每个来源的合计与文件自带汇总比对，不匹配就停**。以下配方来自真实账本（中信/招商 PDF、微信 xlsx、支付宝 GBK csv），换格式时以这些思路重建。

## 微信支付流水.xlsx（发生点）

- 表头位于 0 基索引第 17 行 → `pd.read_excel(path, header=17)`，随后硬编码列名：
  `交易时间 交易类型 交易对方 商品 收支 金额 支付方式 当前状态 交易单号 商户单号 备注`
- 过滤：`交易时间` 非空；金额 `pd.to_numeric` 后转日期列 `%Y-%m-%d`
- 支出：`收支=='支出'`；退款行：`收支=='收入' and 交易类型含'退款'`。**退款按「商户单号」配对原消费行冲减**（不单列退款行）

## 支付宝交易明细.csv（发生点，GBK 编码）

- **编码是 `gbk`，不是 utf-8-sig** —— 用 utf-8 读会崩
- 表头位于 0 基索引第 23 行；数据从第 24 行起，且行首（交易时间）和收支列非空才保留：
  ```python
  with open(csv, encoding='gbk') as f:
      rows = list(csv.reader(f))
  data = [r[:12] for r in rows[24:] if r and r[0].strip() and r[5].strip()]
  ```
  列：`交易时间 交易分类 交易对方 对方账号 商品说明 收支 金额 付款方式 交易状态 订单号 商家单号 备注`
- 退款：`收支=='不计收支' and 商品说明含'退款'`。**退款按「商家单号」配对原支出行冲减**（多数导出里退款与原始交易商家单号相同）；配对不上再按原订单类别/兜底分类。退款不单列展示，见「退款冲减」节
- 金额含负号要处理：支出金额直接 `pd.to_numeric`

## 中信银行流水.pdf

word 级解析：`page.extract_words()`，**按「日期行分带」归组**（不要用 `round(top/4)` 聚行，见坑 7）。列边界：

```
x<90→交易日期  x<157→收入  x<222→支出  x<300→余额  else→明细/摘要
```

- 行首是 8 位日期 `^\d{8}$` 才成行
- **按带归组**：以每笔交易的日期行 top 为锚，相邻日期中点切出一条竖直带（lo=上一日期与当前日期中点，hi=当前与下一日期中点），带内所有字归该笔——右列「附言」单元格可跨两行竖排（如「转账…广州腾讯凯博信息科技有限公/司」），带内右列字必须一并归本笔，否则折行会被算进相邻交易
- 金额用 `^\d[\d,]*\.\d{2}$` 从对应列提取；**明细列取 x0>=265 且非金额的词**——信用卡还款/财付通/蚂蚁基金这些关键字在 x≈273-291，若明细边界只到 222 会丢关键字

## 招商银行流水.pdf

word 级解析，但**金额带符号**（`^-?[\d,]+\.\d{2}$`，负=支出），行首是 `^\d{4}-\d{2}-\d{2}$`：

- **按带归组**：同上，以日期行 top 为锚、相邻日期中点切竖带，带内字（同行交易 + 右列附言）归本笔
- 明细 = 带内除 日期/CNY/RMB/金额/余额/纯英文字（如表头 "Amount"）外的其余词拼起来

## 通用银行流水.csv（测试与直付场景）

无 PDF 时用该格式（也是参考脚本支持的通用银行输入）：

```
日期,摘要,金额,备注
2025-03-01,财付通微信支付,-300.00,结算    # 金额带符号：负=支出，正=收入
2025-03-11,滴滴出行报销,15.00,加班打车报销 # 收入行：供「加班打车报销」识别
```

**收入行（金额>0）单独收集**，用于识别报销（滴滴/加班/差旅报销），绝不混入支出分流。
参考脚本 `parse_bank_csv` 返回 `(支出行, 收入行)`；中信 PDF（收入/支出双列）与招商 PDF（带符号金额）在解析后也统一归并成「支出行 / 收入行」两份。

分流逻辑见 `category-rules.md` 的「银行：分流顺序」。

## 通用坑清单

1. **编码**：支付宝 GBK、银行 utf-8-sig（带 BOM），微信 xlsx 无编码问题
2. **表头行号**：微信 17、支付宝 23——导出文件的说明块行数变了会崩，先数行
3. **PDF 金额正则**：`^[\d,]+\.\d{2}$` 只匹配纯金额词，避免把日期/账号混进金额
4. **多行摘要**：y 聚类后非日期行并入当前行，但合并到「当前组」而非「上一行」，避免双折行错位
5. **余额列藏关键字**：明细列 x 边界要放宽（>=265），否则丢掉类别判断用的关键字
6. **招行/中信差异**：中信金额无符号分列、招商带符号单列——两套逻辑不能混用
7. **附言串行（PDF 最大坑）**：右列附言单元格可跨两行竖排，若用 `round(top/4)` 按物理行聚组，下一笔的附言会串进上一笔。
   - 真实案例 1：中信 PDF 附言「广州腾讯凯博信息科技有限公/司」串进相邻支出行，还混入「第 N 页/共 N 页」页脚
   - 修法：**以日期行 top 为锚、相邻日期中点切竖直带，带内字全归该笔**。同行交易字（如招行内联的对手信息）和右列附言都在带内，天然归并；页脚/相邻行被中界挡在带外。
